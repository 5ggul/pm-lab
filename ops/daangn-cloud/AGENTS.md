# 싸그리 기존 자동화 작업 지침

이 디렉터리가 싸그리 당근 카페 `don-akkineun-sa`의 기존 발행 원본이다. Work/Chat에서 이어 작업할 때 검토용 ZIP으로 프로젝트를 교체하지 말고 최신 `main`과 이 지침을 먼저 읽는다.

## 최신 발행량 지시 — 2026-10-14 후속 수정

사용자가 하루 최대 5건이 아니라 좋은 정보가 있으면 더 많이 발행하도록 수정했다. 현재는 `quality-led` 모드이며 일일·허용 유형·판매자·분야 고정 건수 상한은 null이다. KST 08~22시 매시간 후보를 확인하며 슬롯당 최대 1건, 최소 30분 간격이다. 실제 좋은 정보가 없는 시간은 건너뛴다. 품질 하한·중복 방지·원문 재확인은 낮추지 않는다. 예전 문서의 5건/5회 값을 되살리지 않는다. 자세한 기준은 `QUALITY-LED-VOLUME.md`를 읽는다.

## 사용자 확정 문체

- 상품 글의 공개 기한 라벨은 **할인 기한**이다. 날짜·시각·조건은 원문 근거 그대로 보존한다.
- 사용자가 삭제 요청한 다른 판매처 최저가 미확인 안내 문장은 본문에 다시 넣지 않는다. 그렇다고 미검증 시장 최저가를 주장하지 않는다.
- 원문 `requiredConditions`는 표시 문구로 덮어쓰지 않는다. `editorial-language.mjs`의 동일한 변환으로 생성문과 검수를 대조한다.
- 완성 제목을 글자 수로 잘라내지 않는다. 상품·옵션·가격을 보존할 수 없으면 보류한다. 기본 구성과 조건부 증정을 섞지 않는다.

## 운영 보존

- 기존 GitHub Actions와 Cloudflare clock을 사용한다. 새 스케줄러·중복 자동화를 만들지 않는다.
- `growth-config.json`, 예약 시간, 하루 상한, 소스 설정, 인증, 발행·중복방지 원장은 별도 사용자 요청 없이 바꾸지 않는다.
- 검토용 `automaticPublishing:false` 설정이나 강제 수동승인 기본값을 운영 원본에 통째로 복사하지 않는다.
- `published`, `publishing`, `publish_unknown` 원장을 삭제해서 재발행하지 않는다.
- 실제 게시글의 저장 결과가 불일치하면 성공 처리하지 않는다. 결과 불명은 원문 대조 후 해소한다.
- 홈페이지·게시글·워크플로에 쓰기를 시험하려면 현재 요청의 승인 범위를 확인한다. 비밀값은 출력하지 않는다.

## 검사

`npm ci --ignore-scripts --no-audit --no-fund` 후 `npm run check`를 실행한다. 기존 회귀 검사와 `work-hardening.test.mjs` 검사를 모두 유지한다. 실패한 검사를 삭제해 통과시키지 않는다.

## 아직 별도 작업인 부분

사진 사용권 원장 도입, 실제 옵션·가격의 시각 검수, 다중 이미지 업로더는 이번 운영 전환에 포함되지 않았다. 상품 사진 URL만으로 사용권이 확인됐다고 보고하지 않는다. 기존 이미지 경로를 신규 자동 승인으로 확대하지 않는다.

자세한 범위는 `WORK-ROLLOUT-20261014.md`를 읽는다.
