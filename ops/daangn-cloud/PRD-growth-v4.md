# 싸그리 당근 회원 성장·콘텐츠 자동화 PRD v4

- 작성일: 2026-09-26
- 상태: 구현 검토용 제안. 이 문서 작성으로 운영 설정·코드·게시물을 변경하지 않는다.
- 대상: 기존 당근 커뮤니티 자동 발행 시스템. 네이버 카페 「싸게살자」 PRD와 별도 문서다.
- 핵심 목표: 읽고 끝나는 할인 피드를, 이웃에게 공유하고 가입한 뒤 다시 찾는 생활정보 커뮤니티로 발전시킨다.
- ‘사람처럼’의 정의: 독자의 상황에 맞게 정확한 정보를 선별하고 자연스럽게 설명한다. 실제 회원을 사칭하거나 경험·댓글·인기를 만들어내지 않는다.

## 1. 현황과 설계 전제

### 1.1 기존 작업 기록에서 확인한 내용

「당근카페 자동화 진행」의 최근 완료 보고에 따르면 다음 기능이 적용돼 있다. 이번 문서 작성에서는 저장소 코드나 실시간 운영 로그를 재검증하지 않았으므로 구현 전 확인해야 한다.

- GitHub Actions에서 수집 → 사실 검증 → v3 카피 생성 → 중복 검사 → 당근 발행 → 상태 저장.
- `Fact/Claim Ledger`, 최근 100개 글 비교, 의미 중복·문장 반복·가짜 경험·과장 문구 차단.
- 하루 15건은 상한이며, 후보가 부족하거나 품질 검사를 통과하지 못하면 발행하지 않음.
- 매일 23:40 KST 조회수 수집 및 전략 가중치 학습. 일일 변화 ±5%, 가중치 범위 0.75~1.25.
- 마지막 완료 보고는 당일 9건 발행, 조회수 12개 측정 성공. 이는 장기 성과의 기준선이 아니다.
- 백업 작업은 시간대별 발행 목표 부족을 보고하고 있음. ‘양질 후보가 없으면 미발행’ 원칙과 목표 건수 기준 백업 사이의 충돌 여부를 확인해야 한다.

### 1.2 아직 확인되지 않은 것

현재 회원 수, 가입·탈퇴 이력, 주 활동 지역, 게시물의 비회원 공개 범위, 회원별 재방문 지표, 공유·저장 수 노출 여부, 유입경로 추적 가능 여부는 미확인이다. 모임·카페 등 실제 당근 서비스 지면과 허용되는 게시·자동화 방식도 운영 화면 및 해당 지면의 공식 안내로 확인한다.

지역은 추정하지 않는다. `primaryRegion` 미설정 시 지역 행사 자동 발행은 보류하고 전국에서 동일하게 이용 가능한 정보만 후보로 받는다. 기존의 여성·주부·맘·시니어 가설은 유지하되, 나이·성별을 추정하기보다 ‘장보기 절약 / 가족 주말 / 생활 문제 해결’이라는 필요를 기준으로 편집한다.

| 문제 | v4의 대응 | 확인할 증거 |

| 조회수만 높은 주제를 반복할 수 있음 | 도달·가입·재방문·참여 목적을 구분 | 목적별 관측 가능한 성과 |

| 회원은 소비만 하고 운영 계정만 글을 씀 | 질문 수집·제보 검증·후속 답변 순환 | 실제 회원 제보·질문·게시글 |

## 3. 목표와 지표

아래 수치는 업계 기준이나 성과 보장이 아니라 초기 실험 목표다. 1~2주차 기준선이 확보되면 절대 수와 함께 확정한다. 비교 기간의 발행량과 유입 활동을 함께 기록한다.

| 목표 | 정의 | 8주차 제안 목표 |
|---|---|---|
| 회원 성장 | 일일 회원 수 차이의 주간 합계. 가입·탈퇴가 별도 관측되면 둘 다 기록 | 주간 순증 기준선 대비 +30% |
| 가입 후 가치 | 신규 가입자 중 7일 내 재방문 또는 의미 있는 활동을 한 비율 | 기준선 대비 +10%p, 회원별 측정 가능할 때만 |
| 정보 도달 | 같은 콘텐츠 유형·게시 후 경과시간의 24h 조회수 중앙값 | 기준선 대비 +20% |
| 참여 | 발행 후 72h 내 운영 계정 외 회원의 실질 댓글이 1개 이상인 글 비율 | 기준선 대비 +10%p |
| 회원 기여 | 실제 회원이 직접 작성한 유효 제보·질문·후기 수 | 주 3건을 초기 목표로 검토 |
| 품질 | 중대한 사실 오류 / 허위 경험 / 중복 발행 | 각각 0건 |

기준선이 0이면 상대 증가율을 계산하지 않고 절대 건수를 사용한다. 기준선 10명에서 13명으로 늘어난 것과 1,000명에서 1,300명으로 늘어난 것을 동일한 확신으로 해석하지 않는다.

### 3.1 측정 가능성 계약

- 각 지표에 `available / unavailable / partial`, 출처, 수집 시각, 표본 수를 기록한다. 수집 불가는 `null`이며 0으로 처리하지 않는다.
- 회원 수만 있으면 **순증**만 안다. 총가입·탈퇴·회원 유지율은 추정 생성하지 않는다.
- 전체 조회수만 있으면 클릭률·고유 방문자 수·공유율·가입 전환율을 계산하지 않는다.
- 선택형 가입 경로 질문이나 추적 가능한 공식 초대 링크가 지원되는 경우만 경로별 전환을 기록한다. 자기보고는 정확한 귀속이 아니라 참고 데이터다.
- 링크 클릭은 가입이 아니다. 게시 후 회원 수 증가도 그 글의 가입 성과라는 인과 증거가 아니다.
- 회원별 재방문을 합법적이고 정상적인 기능으로 측정할 수 없으면 ‘반복 댓글 참여자’ 등을 별도 보조지표로 사용한다. 이를 독자 유지율이라고 부르지 않는다.
- 개인정보 수집 없이 가능한 집계 지표를 우선한다. 회원 식별자가 꼭 필요한 집계는 최소한으로 보관하고 보관 기간을 설정한다.

## 4. 회원을 모으고 남게 하는 흐름

### 4.1 발견 → 유용함 확인 → 가입 → 재방문 → 기여

1. 발견: 비회원에게 실제 노출 가능한 지면·공유 경로부터 확인한다. 이미 회원에게만 보이는 글을 ‘신규 유입 채널’로 계산하지 않는다.
2. 유용함 확인: 공개 가능한 글은 대상, 혜택, 핵심 조건을 본문에서 바로 알려준다. 답을 감춘 채 가입을 요구하지 않는다.
3. 가입: 소개와 고정글에 운영 주제, 실제 발행하는 연재, 이용 방법을 짧게 표시한다.
4. 재방문: 주말 일정표·마감 모음·생활비 비교처럼 반복해서 확인할 이유를 제공한다.
5. 기여: 제보·질문을 받아 확인한 뒤 다음 정보에 반영한다. 사용 허락을 받은 회원 제보만 익명 또는 동의한 이름으로 소개한다.

### 4.2 필요한 커뮤니티 장치

| 장치 | 내용 | 완료 기준 |
|---|---|---|
| 소개문 | ‘장보기 할인, 주말 나들이, 놓치기 쉬운 생활정보를 조건까지 확인해 정리합니다’ | 실제 운영 범위와 일치 |
| 새 회원 고정글 | 대표 글 3개, 연재 일정, 관심 주제 남기는 방법 | 링크 정상·지난 행사 제외 |
| 주간 생활정보 모음 | 검증한 이번 주 정보 3~5개와 각각의 대상·조건 | 기존 글 링크만 나열하지 않고 선택 이유 포함 |
| 질문·제보 안내 | 지역/대상/궁금한 점을 최소 항목으로 받음 | 제보가 검증 큐에 들어감 |
| 정정 안내 | 변경된 가격·마감·취소 내용을 원문에 표시 | 최신 확인 시각·변경 이유 표시 |

초기에는 고정글·소개문·연재 구성 3가지만 정비한다. 실제로 지속 발행할 수 없는 일정을 약속하지 않는다.

### 4.3 외부 유입 실험

- 1순위: 실제 플랫폼에 제공되는 공유·초대 기능. 글 자체로 도움이 되는 요약을 함께 제공한다.
- 2순위: 운영자가 보유한 관련 사이트·블로그에 해당 주제의 보충 자료와 커뮤니티 안내를 연결. 현재 글과 관련 있을 때만 연결한다.
- 3순위: 홍보가 허용되는 지역 기관·커뮤니티와의 협업. 배포 문안과 링크를 준비하되 자동 연락·대량 게시 기능은 범위에 포함하지 않는다.
- 유료 유입은 별도 선택 사항이다. 당근 공식 광고 상품은 확인됐지만 이 커뮤니티의 가입 페이지를 목적지로 사용할 수 있는지는 미확인이다. 적합성·추적 가능성·예산이 정해지기 전에는 집행하지 않는다.
- 공유 요청을 모든 글에 붙이지 않는다. ‘누가 받으면 도움이 되는가’가 분명한 글이 먼저다.

## 5. 추가할 주제와 콘텐츠 포트폴리오

현재 인기라고 검증한 주제 목록이 아니라 **우선 검증할 편집 가설**이다. 실제 바이럴 여부는 배포 후 측정한다.

초기 비중은 최근 20개 발행을 기준으로 핫딜 35%, 생활정보·비교 25%, 지역·주말 20%, 마감·주간 모음 10%, 질문·제보 10%를 목표로 한다. 적격 후보가 없으면 빈 슬롯을 억지로 채우지 않는다. 지역 미설정 시 지역 비중을 다른 유형에 강제 전가하지 않는다.

| 주제 묶음 | 구체적인 후보 | 공유할 이유 | 다시 찾을 이유 | 출처·필수 검증 |
|---|---|---|---|---|
| 장바구니 단가 비교 | 같은 규격 세제·물티슈·생수의 배송 포함 단가 | 가족 장보기 결정에 바로 도움 | 주간 가격 관측 | 판매처 원문, 용량·수량·배송·쿠폰 대상 |
| 가까운 주말 나들이 | 해당 지역 무료 전시, 도서관 체험, 공공시설 프로그램 | 함께 갈 사람에게 전달 | 매주 새로운 일정 | 주최기관, 지역·날짜·예약·추가 비용 |
| 오늘·이번 주 마감 | 실제 종료일이 있는 신청·예약·쿠폰 | 대상자가 놓치기 전에 전달 | 주간 마감표 | 공식 마감 시각·대상·중복 혜택 조건 |
| 동네 공공서비스 | 도서관 대여, 공구 대여, 생활 편의 서비스 | 가까운 사람에게 실용적 | 지역별 업데이트 | 지자체·기관, 거주 요건·이용료 |
| 생활비 착각 바로잡기 | 묶음보다 낱개가 싼 실제 사례, 무료배송 최소금액 비교 | 짧고 의외인 계산 결과 | 생활비 비교 연재 | 동일 조건 계산, 확인 시각 |
| 계절 생활 체크 | 이사·장마·겨울 준비 시 필요한 공식 체크리스트 | 가족과 준비 항목 공유 | 계절별 새 체크리스트 | 기관·제조사 자료, 의료 조언 제외 |
| 가족 일정표 | 연령 조건이 맞는 공공 프로그램 모음 | 부모·보호자 간 전달 | 접수 시작·변경 업데이트 | 연령·보호자 동반·예약·지역 확인 |
| 회원 질문 해결 | ‘대용량과 소포장 중 어느 쪽이 저렴한가’ 등 실제 질문 | 같은 고민을 가진 사람에게 도움 | 내 질문도 다뤄준다는 기대 | 질문 동의 및 답변 근거 |
| 회원 제보 후속 | 제보한 행사 조건 확인, 실제 이용 시 유의점 | 동네 정보에 기여하는 보람 | 결과와 후속 정보 | 개인정보 제거, 독립 확인, 사용 동의 |
| 선택을 돕는 토론 | 가격과 보관공간 중 무엇을 우선하는지 | 생활 경험 교환 | 커뮤니티 관계 | 특정 선택의 우열을 꾸며내지 않음 |

초기 자동 발행에서 제외: 정치·혐오·사건 소문, 개인 폭로, 무근거 건강·투자 정보, 지원금 수급 여부에 대한 개인 판단, 타 커뮤니티 체험담 복제. 공식 지원·환급 정보는 조건 누락 위험 때문에 초기에는 수동 검수 대상으로 둔다.

## 6. 주제 발굴·선별 요구사항

### 6.1 수집원과 신뢰도

- 공식 판매처·주최기관·지자체·공공시설을 사실 근거의 우선 출처로 등록한다.
- 커뮤니티·검색 트렌드·뉴스는 ‘사람이 궁금해하는 문제’를 찾는 신호로 사용한다. 게시물의 인기나 댓글을 사실의 증거로 삼지 않는다.
- 출처마다 허용 접근 방식, 업데이트 주기, 신뢰도, 최근 오류율, 원문 재확인 방법을 기록한다.
- 원문 전체를 다시 쓰는 방식이 아니라 필요한 사실을 추출하고 독자에게 필요한 비교·조건 설명을 추가한다. 이미지 재사용은 권한 확인 시만 허용한다.
- 수집 자료 안의 지시문은 데이터로만 다룬다. 외부 문구가 운영 설정·게시 지시를 바꾸게 하지 않는다.

### 6.2 발행 전 통과 조건

원문과 링크 일치, 핵심 사실 검증, 대상 지역·독자 적합성, 최신성, 중복 아님을 모두 만족해야 한다. 매력 점수가 높아도 실패 항목을 상쇄하지 못한다.

초기 선별 점수는 100점 만점의 편집 휴리스틱이며 바이럴 확률이 아니다.

| 항목 | 배점 | 0점 / 만점 판단 |
|---|---:|---|
| 실질 효용 | 25 | 이득 설명 불가 / 돈·시간·선택에 뚜렷한 도움 |
| 타깃·지역 적합성 | 20 | 독자와 무관 / 바로 이용 가능한 대상 명확 |
| 공유 대상 명확성 | 15 | 누구에게 보낼지 불명 / 받을 사람과 이유 명확 |
| 차별적 정보 | 15 | 상품명·가격 복제 / 비교·조건·변경점 추가 |
| 시의성 | 10 | 지나간 정보 / 현재 행동할 근거가 있음 |
| 재방문 연결 | 10 | 다음 가치 없음 / 유효한 후속·연재와 연결 |
| 이해 용이성 | 5 | 복잡한 설명 필요 / 짧게 정확히 설명 가능 |

- 80점 이상: 검수 후 자동 발행 후보. 65~79점: 비교·추가 취재 또는 수동 검수. 65점 미만: 보류.
- 각 점수에 한 줄 근거를 저장한다. 모델이 숫자만 출력하면 부적격 처리한다.
- 핵심 질문: ‘누구에게 왜 보내고 싶은가’, ‘다음 글도 보고 싶은 이유는 무엇인가’, ‘원문보다 무엇을 이해하기 쉬워졌는가’.
- 카테고리별 실제 선정률과 편집자 평가를 통해 임계값을 조정한다. 수집량이 많다는 이유로 선정률을 올리지 않는다.

## 7. 자연스럽고 양질인 글의 생성·검수

### 7.1 기존 v3에 추가할 편집 단계

`사실 추출 → 근거 장부 → 독자·상황 지정 → 한 가지 편집 관점 선택 → 초안 → 사실 대조 → 독자 가치 검수 → 반복 검사 → 발행 직전 재확인`

작성 전 `readerNeed`, `editorialAngle`, `whyNow`, `shareRecipient`, `returnReason`을 정한다. 해당 없는 항목은 null로 두며 억지 공유·가입 문장을 만들지 않는다. 한 글에 전달할 핵심은 하나로 좁힌다.

### 7.2 글쓰기 기준

- 제목은 정보를 선택할 수 있게 한다. 실제 혜택·지역·대상·마감 중 중요한 항목부터 쓴다. ‘모르면 손해’처럼 사실 없이 불안을 자극하지 않는다.
- 첫 문장은 제목의 반복이 아니라 독자에게 중요한 조건이나 차이를 알려준다.
- 본문은 이득, 적용 조건, 제외 대상, 행동 방법 중 필요한 것만 담는다. 150~450자 짧은 정보, 450~900자 비교·모음은 시작 가이드이며 사실 전달이 길이보다 우선이다.
- 링크를 열어야만 가격 조건을 알게 만들지 않는다. 카드·멤버십·쿠폰·최소 주문·배송비 조건을 본문에서 함께 설명한다.
- 인간적인 느낌을 위해 오타·과한 애교·허위 사투리·가짜 일상을 넣지 않는다. 말투는 친근하되 담백하게 유지한다.
- ‘저도 샀어요’, ‘우리 애가 좋아해요’, ‘이웃들이 난리예요’는 실제 검증 자료와 사용 권한 없이는 작성하지 않는다.
- 회원 제보를 인용하면 운영자가 직접 겪은 경험으로 바꾸지 않는다. 실제 경험과 운영자의 사실 확인을 구분한다.
- 질문은 답변이 다음 콘텐츠에 도움이 되는 경우만 사용한다. 질문 글은 초기 최대 주 2회이며 의미 없는 ‘어떻게 생각하세요?’를 붙이지 않는다.
- 제목 구조의 다양성보다 정보의 적절성이 우선이다. 숫자만 바꾼 동일 글은 막되, 자연스러운 한국어 어미가 같다는 이유만으로 무한 재작성하지 않는다. 기존 반복 규칙의 오탐은 샘플 검토 후 수정 제안한다.
- 제휴·협찬이 있으면 그 관계를 독자가 알아볼 수 있게 표시한다.

### 7.3 편집 품질 평가

사실 정확성은 점수가 아닌 필수 통과 조건이다. 그다음 독자 효용 30, 조건 명료성 25, 원문 대비 추가 가치 20, 자연스러움 15, 읽기 편함 10으로 평가한다. 총 85점 이상이어도 핵심 조건 누락·허위 경험·근거 없는 수치·기만 제목이 있으면 발행 불가다.

계산·날짜·가격은 결정적 코드로 검증한다. 문장 품질은 별도 비평 단계로 평가하되 모델의 자기평가만으로 정확성을 보장하지 않는다. 최초 30개 초안은 운영자가 전수 검토하고, 안정화 뒤에는 주 10개 무작위 표본과 정정·신고 글 전부를 검토한다.

### 7.4 형식 예시 — 가상 값, 실게시 금지

다음은 말투와 정보 배열을 설명하기 위한 가상 데이터다. 실제 할인·행사를 뜻하지 않는다.

**단가 비교형**

제목: `같은 세제인데, 2개 묶음보다 낱개 두 개가 1,000원 싸요`

본문: `같은 1L 제품으로 비교하면 낱개 2개는 배송비까지 11,000원, 묶음은 12,000원이에요. 낱개 쪽은 2개부터 무료배송이고 별도 쿠폰 조건은 없어요. 한 개만 필요하면 배송비가 붙으니 수량을 먼저 확인하면 됩니다. [각 판매처 원문]`

검증 데이터: 낱개 5,500원×2, 2개 구매 무료배송; 묶음 12,000원 무료배송; 동일 제품·옵션. 하나라도 다르면 문장을 다시 계산한다.

**지역 행사형**

제목: `[지역] 토요일 어린이 체험, 입장은 무료지만 예약이 필요해요`

본문: `[기관]에서 [날짜]에 여는 체험이에요. 대상은 [연령]이고, 보호자 동반 조건이 있어요. 입장료는 없지만 [유료 항목]은 별도라 신청 전에 확인해두면 좋아요. 예약은 [공식 링크].`

대괄호가 남아 있으면 자동 발행을 차단한다. 실제 예시 문장은 운영 중 반복 템플릿으로 강제하지 않는다.

## 8. 발행 운영과 최신성

- 초기 편집 계획은 하루 최대 6개 슬롯으로 시작하고 기존 상한 15개와 구분한다. 적격 글이 2개면 2개만 발행한다. 수량 확대는 2주 이상 관찰 후 결정한다.
- 슬롯은 오전의 실용 정보, 오후의 비교·질문, 저녁의 다음 일정 등 가설로 시작한다. 최적 시간이라고 단정하지 않는다.
- 동일 판매처 하루 최대 2개, 동일 세부 주제 연속 발행 금지. 기존 더 엄격한 상한이 있으면 그 값을 우선한다.
- 백업 작업은 누락된 예약 실행·기술 실패만 복구한다. `quality_rejected`, `no_candidate`, `category_cap`, `expired`는 정상 미발행이며 부족 건수 채우기를 실행하지 않는다.
- 가격·재고·한정 쿠폰은 발행 직전 15분 이내 다시 확인하는 것을 기본값으로 둔다. 접근이 안 되면 가격을 단정해서 게시하지 않는다.
- 행사는 발행 당일과 가능한 경우 시작 전날 취소·예약 변경을 확인한다. 확인 주기는 출처의 변동성과 접근 제한에 맞춰 설정한다.
- 게시 후 종료·품절·취소가 확인되면 기존 글의 상태를 갱신한다. 편집 기능이 없으면 운영자 수정 큐로 넘기고 중복 신규 글로 덮지 않는다.
- 모든 후보가 거절되면 `skip`으로 종료한다. 품질 기준을 낮춘 예비 문구를 발행하지 않는다.

## 9. 시스템·데이터 요구사항

### 9.1 파이프라인

`source registry → collectors → fact ledger → topic scorer → editorial planner → copy engine → QA → queue → publish recheck → publisher → metrics → daily report / bounded learning`

기존 발행기는 가능한 한 유지하고 그 앞에 편집 계획·주제 점수·검수 큐를 추가한다. 아래 파일명은 제안이며 기존 코드 구조 확인 후 확정한다.

| 구성요소 | 추가 책임 |
|---|---|
| `source-registry.json` | 출처 신뢰도·지역·허용 수집 방식·갱신 주기 |
| `topic-scorer.mjs` | 근거 있는 주제 점수, 보류 사유 |
| `editorial-planner.mjs` | 목적·연재·카테고리·지역·슬롯 배정 |
| `copy-engine` 확장 | 독자 상황·편집 관점에 맞춘 초안 |
| `quality-gate` 확장 | 조건 누락·비교 계산·실제 추가 가치 검사 |
| `review-queue.json` | 검토 필요 글·정정·신규 유형 |
| `community-metrics.json` | 회원 수 및 실제 제공되는 커뮤니티 지표 |
| `experiment-registry.json` | 실험 가설·배정·종료 조건·결론 |

### 9.2 핵심 스키마

| 엔터티 | 필수 필드 |
|---|---|
| Candidate | id, canonicalUrl, sourceId, fetchedAt, type, topic, region, audienceNeed, validUntil, semanticKey |
| Claim | claimId, candidateId, field, value, unit, conditions, sourceUrl, observedAt, verificationStatus |
| EditorialPlan | contentId, objective, seriesId, readerNeed, angle, shareRecipient, returnReason, scoreBreakdown, plannedAt |
| Draft / QA | draftId, contentId, claimRefs, text, ruleVersion, promptVersion, modelVersion, hardFailures, qualityScores, reviewStatus |
| Published | postId, contentId, postUrl, publishedAt, contentHash, idempotencyKey, strategy, experimentId, status |
| Metrics | postId, measuredAt, ageHours, views, reactions, comments, shares, saves, availability, collectionStatus |
| CommunitySnapshot | measuredAt, members, joins, leaves, availability, source |
| Experiment | id, hypothesis, primaryMetric, eligibility, assignment, startAt, stopRule, sampleSize, result |

가격·금액 원자료와 계산 결과는 별도 필드로 관리한다. 학습 입력에는 오류·실패 여부를 반드시 포함한다. 외부 원문 전체나 회원 개인정보를 로그에 불필요하게 저장하지 않는다.

### 9.3 중복·실패 복구

- 상태 전이: `collected → verified → planned → drafted → approved → publishing → published`. 별도 종료 상태 `rejected / expired / failed / publish_unknown`.
- 동일 semanticKey와 정보 버전으로 idempotencyKey를 만들고 발행 잠금과 영속 기록을 사용한다. 실질 가격·일정 변경은 같은 원문에 대한 새 정보 버전으로 기록한다.
- 게시 요청 후 응답을 잃으면 `publish_unknown`으로 둔다. 실제 게시물 존재 여부를 확인하기 전에는 재발행하지 않는다.
- 주 발행·백업·학습 작업의 동시 실행 충돌을 검사한다. 학습이 발행 이력을 덮어쓰지 않게 파일 소유권 또는 저장 트랜잭션을 분리한다.
- 댓글은 초기에 읽기·분류·답변 초안만 지원한다. 가격·참가 조건 등의 답변도 근거가 필요하며 자동 댓글 게시·자동 DM은 이번 범위에 포함하지 않는다.

## 10. 성과 학습과 실험

### 10.1 일일 학습

기존 23:40 수집 및 제한된 가중치 변경을 유지하되 측정 목적을 분리한다.

- 도달형: 동일 연령대의 게시물 조회 성과. 노출 수가 없으면 클릭률로 부르지 않는다.
- 공유형: 실제 공유 수가 제공될 때만 공유를 학습한다. 데이터가 없으면 공유 전략은 편집 가설로 남긴다.
- 가입형: 귀속 가능한 가입 데이터가 있을 때만 글 전략의 가입 성과를 업데이트한다.
- 재방문형: 실제 반복 방문이 없으면 연재 반응·반복 참여를 보조 평가한다.
- 결측 지표의 가중치를 조회수로 자동 재분배하지 않는다. 가능한 지표와 불가능한 지표를 따로 보고한다.
- 일일 1회 스냅샷의 차이는 그 두 관측 사이의 증가량이다. 게시 후 정확한 24h 조회라고 표시하려면 별도 24h 측정 작업이 필요하다. 구현 전에는 실제 경과시간 구간을 표시한다.

유형·시간대·게시 경과시간을 맞춰 비교한다. 작은 집단은 상위 집단 평균 쪽으로 보수적으로 보정하고 중앙값 0·조회수 역행·누락·삭제 상태를 예외 처리한다. 기존 ±5%/일, 0.75~1.25 제한은 유지한다.

전략 자동 조정은 초기 기준으로 비교 가능한 글 20개 이상, 7일 이상 관측 후 허용한다. 그 전에는 데이터만 쌓는다. 이 최소치는 통계적 유의성을 보장하지 않는다. 측정 성공률 90% 미만이면 학습을 멈추고 기존 설정을 유지한다.

신규 주제 탐색 슬롯은 최대 20%로 두되 품질 기준은 동일하다. 사실 검증·출처 기준·허위 경험 차단 규칙은 성과 학습이 변경할 수 없다.

### 10.2 우선 실험

| 실험 | 가설 | 주지표 | 통제할 요소 |
|---|---|---|---|
| 단품 안내 vs 동일 조건 단가 비교 | 비교 정보가 실질 참여와 공유에 유리 | 실질 댓글 발생률, 공유는 관측 가능 시 | 카테고리·가격대·시간대 |
| 검증한 개별 정보 vs 주간 선별 모음 | 모음이 연재 재방문에 유리 | 재방문 가능 지표, 없으면 반복 참여 | 정보 유효기간·구성 수 |
| 소개·고정글 개선 | 가입 후 기대를 알면 참여가 늘어남 | 가입 후 7일 활동, 없으면 집계 변화 | 유입 활동·발행량 변화 기록 |
| 회원 질문에서 출발한 글 | 실제 질문에 답하는 글이 기여를 유도 | 후속 회원 질문·제보 수 | 유사한 주제·발행 시간 |

동시에 한 가지 주요 변수를 바꾼다. 가능한 범위에서 적격 글을 조건별로 균형 배정하며, 같은 글을 중복 게시해서 A/B 테스트하지 않는다. 최소 2주 관측하고 표본이 부족하면 ‘결론 유보’로 남긴다. 주제 차이가 큰 단순 전후 비교는 탐색 결과로만 해석한다.

### 10.3 주간 운영 보고

회원 순증 / 지표 측정 가능성 / 유형별 조회 중앙값 / 실제 회원 참여 / 주제 선정·탈락 사유 / 정정·품절 처리 / 다음 주 유지·축소·탐색 항목을 한 화면에 정리한다. ‘워크플로 성공’과 ‘회원 성장’을 별도 상태로 보여준다.

## 11. 도입 순서

| 단계 | 범위 | 완료 조건 |
|---|---|---|
| 1주차: 현황·관측 | 실제 코드·서비스 지면 확인, 지표 가용성, 지역 설정, 백업 조건 점검 | 알 수 있는 값과 없는 값 구분, 목표량 강제 보충 제거 설계 |
| 2주차: 편집 기반 | 소개·고정글 초안, 출처 등록, 점수·편집 계획, 최근 글 기준선 | 신규 초안 30개 검수, 자동 게시 없이 시뮬레이션 |
| 3~4주차: 제한 출시 | 단가 비교·지역 주말·마감 모음 중 검증된 유형부터 적용 | 기능별 플래그, 일일 상한, 정정·실패 복구 통과 |
| 5~6주차: 참여·유입 | 질문 수집, 제보 확인, 연재, 측정 가능한 공유·유입 실험 | 실제 회원 반응 기록, 원인 불명 성장을 특정 글에 귀속하지 않음 |
| 7~8주차: 조정 | 충분한 표본의 주제·형식만 확대 | 목표 평가, 부족한 데이터 명시, 다음 주기 계획 |

P0는 관측 가능성·품질·중복·백업 복구, P1은 신규 콘텐츠와 가입 동선, P2는 공유 자산·추가 유입 실험이다. 성장 기능 때문에 P0를 우회하지 않는다.

## 12. 출시 수용 기준

1. 가격·배송·쿠폰·단가 계산이 서로 다른 10개 케이스에서 필수 조건 누락과 잘못된 비교를 차단한다.
2. 무료 입장/유료 체험, 예약 마감/행사일, 지역 제한을 구분한다. 지역 미설정 후보는 자동 게시하지 않는다.
3. 원문 불일치·종료·재확인 실패·허위 체험·가상 예시의 미치환 문구를 발행 전에 차단한다.
4. 유효한 사실만 담아도 독자 가치가 없는 초안은 보류한다. 30개 사전 표본에서 중대한 사실 오류 0건, 운영자 평가상 수정 없이 게시 가능한 글 80% 이상을 초기 기준으로 삼는다.
5. 발행 요청 타임아웃과 주·백업 동시 실행을 주입한 테스트에서 게시물 중복이 발생하지 않는다.
6. 품질 부족 미발행을 백업이 보충하지 않고, 기술 실패만 재시도한다.
7. 지표 수집 실패가 0으로 저장되지 않는다. 조회수만 있을 때 가입·공유·유지율을 생성하지 않는다.
8. 정확한 24h 측정과 일일 스냅샷 차이를 구분한다. 데이터 부족·성공률 미달·중복 학습 실행에서 가중치가 변하지 않는다.
9. 품절·취소 확인 시 원문 수정 또는 운영자 수정 큐가 생성된다.
10. 모듈별 기능 플래그로 신규 작성·주제 선정 기능을 되돌려도 발행 이력과 지표가 보존된다. 롤백이 기존 발행 글을 자동 삭제하지 않는다.

## 13. 중단·복구 조건

- 잘못된 가격·날짜·자격 조건 등 중대한 오류가 확인되면 해당 유형 자동 발행을 중지하고 원인·영향 글을 검토한다.
- 인증 실패·게시 제한·정책 관련 안내가 발생하면 발행 재시도 폭주를 막고 상태를 운영자에게 표시한다.
- 새 기능이 없던 시기 대비 품질 지표가 나빠지면 해당 기능 플래그만 되돌린다. 낮은 조회수 한두 건만으로 전체 시스템을 바꾸지 않는다.
- 회원 불편·신고는 실제 접근 가능한 신호만 사용한다. 관측할 수 없다는 것을 ‘불편 없음’으로 해석하지 않는다.

## 14. 구현 전에 확인할 항목

현황 점검에서 아래 값을 채운다. 미확인 값으로 기능을 구현하거나 성과를 꾸미지 않는다.

- 실제 저장소·브랜치·운영 워크플로·현재 v3 규칙과 가중치 파일 구조.
- 당근의 정확한 서비스 지면, 게시물 공개 범위, 초대·공유 기능, 허용되는 운영 접근 방식.
- 주 활동 지역과 회원이 원하는 생활정보 범위.
- 현재 회원 수·최근 14일 발행/조회 자료 및 관측 가능한 추가 지표.
- 운영자가 검수할 수 있는 시간과 신규 유형 전수 검수 담당.
- 외부 유입에 활용할 보유 채널, 이미지 사용 권한, 협찬·제휴 여부.
