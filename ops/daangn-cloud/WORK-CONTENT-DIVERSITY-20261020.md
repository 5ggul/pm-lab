## 변경 내용

### 본문 구성과 사실 검수

`editorial-diversity.mjs`가 상품용 18개, 정보용 24개 구성 계획을 제공한다. 실제로 채워진 문단의 역할과 순서로 구조 식별자를 만든다. 내용 유형이나 계획 이름만 바꾼 같은 구조는 새 구조로 세지 않는다. 최근 12개 관리 구조와 8개 문단 틀의 재사용을 차단하고, 시작·마무리의 연속 반복에 감점을 준다.

가격·비교 기준·할인액·단가·배송 합계는 동일한 검증된 값에서 승인된 표현만 생성한다. 생성기와 검수기가 표현 레지스트리를 공유한다. 필수 사실, 구매 제한, 배송 지역, 가격 이력, 출처를 모두 보존한다. 상품명·옵션·증정 구분과 공개 라벨 `할인 기한`을 유지한다.

표현을 바꾸어 동일 상품을 다시 선택하는 회귀를 막기 위해 콘텐츠 식별자와 정규화한 판매 링크를 함께 확인한다. 옛 본문에만 링크가 있어도 중복으로 감지한다. 기존의 검증된 가격 하락 재알림은 새 콘텐츠 버전으로 허용하며, 같은 가격 버전과 미확정 제출은 계속 차단한다.

### 편성과 제출 이력

`submissionHistory()`는 확인된 성공과 `publishing`/`publish_unknown`을 상태를 유지한 채 합쳐 발행량·중복·다양화 판단에 사용한다. 같은 공개 URL 또는 예약을 중복 계산하지 않는다. 미확정 기록에 `publishedAt`을 새로 만들지 않으며 성공 지표는 확인된 기록만 집계한다.

정보가 없는 옛 미확정 기록을 비판매 정보로 간주하지 않는다. 총량·유형별 상한 및 판매 연속 제한에서는 보수적으로 자리를 예약한다. 상품 경로와 정보 전용 경로가 동일한 유형별 제출량 계산을 사용한다.

`utility-selection.mjs`는 검증·품질 하한·분야 상한을 먼저 적용한 뒤 유형·시리즈·분야·본문 구조의 다양성을 순위에 반영한다. 품질 1점 차이가 모든 다양성 점수를 압도하던 계산을 조정한다. 검증된 비판매 후보가 없으면 건수를 채우기 위한 판매글로 대체하지 않는다.

### 게시 후 재확인

제출 직후 공개 HTML에서 게시판 정보를 읽지 못할 때, 이미 관측한 동일 카페의 동일 게시글만 다시 읽는다. 제목·본문·게시판·사진 수·URL·게시 시각의 일치 검사는 그대로 적용한다. 링크를 찾지 못했거나 내용이 다르면 `publish_unknown`으로 남긴다.

제출 전에 원문과 문체 메타데이터를 원장에 저장하고, 확인 후에는 관측된 게시판·해시·시각·파서 진단을 남긴다. 인증 정보는 이 스냅샷에 저장하지 않는다. 옛 기록을 지워 다시 발행하는 복구 방법은 사용하지 않는다.

## 검증과 운영 확인의 경계

- 필수 설치 명령: `npm ci --ignore-scripts --no-audit --no-fund`
- 통합 회귀 검사: `npm run check`
- 새 검사는 구조 재사용, 사실 누락·가격 변조, 장기간 합성 정보 편성, 동일 상품·가격 버전 중복, 미확정 제출 회계, 공개 결과 재확인을 포함한다.
- 기존 가격·배송·조건·재알림·일일 상한·Cloudflare clock 검사를 유지한다. 단일 문구만 기대하던 일부 검사는 승인된 표현 안에서 같은 사실을 보존하는지 확인하도록 바꿨다.
- PR의 기존 GitHub Actions는 검사와 collect-only를 실행한다. PR에서 실제 게시 인증을 사용하지 않는다.
- 운영 main 반영 후 기존 정기 실행이 새 코드를 사용한다. 코드 커밋만으로 heartbeat를 갱신하거나 시험 글을 제출하지 않는다.
- 실제 다음 제출의 저장 결과와 이후 6~72시간 성과 표본은 별도 관측 대상이다. 코드·합성 검사 통과를 실제 발행이나 성장 성과로 보고하지 않는다.
