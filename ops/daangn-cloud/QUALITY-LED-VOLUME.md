# 싸그리 발행량: 좋은 정보가 있으면 5건 이후에도 발행

2026-10-14 사용자 후속 지시: "최대 5개는 아니고 좋은거 있으면 많이 올려도 돼". 이 문서는 이전 하루 5건 상한·하루 5회 슬롯 보존 지시를 대체한다. 다른 품질·문구·범위·인증 지시는 유지한다.

## 적용 기준

- `publishingMode: quality-led`. 일일 총량, 상품성 콘텐츠, 허용된 hotdeal/tip 유형, 판매자, 카테고리의 고정 건수 상한은 `null`이다. `null`은 상한 없음이고 `0`은 비활성이다. `?? 5` 또는 숫자 비교로 null을 0/5로 바꾸면 안 된다.
- 좋은 정보가 없으면 발행하지 않는다. 5건·10건·15건은 목표량이 아니다. 범위 밖 콘텐츠나 미검증 정보를 추가 시간대에 채우지 않는다.
- 품질 점수와 사실 검증이 우선이다. 상품 정보 하한 92점, 원고 하한 72점, 자동 선별 편집 점수 80점과 원문 재확인을 유지한다.
- 판매자·카테고리 반복은 비슷한 품질일 때의 우선순위에 반영한다. 같은 카테고리라는 이유만으로 다른 유용한 상품을 일괄 차단하지 않는다. 동일 상품·원문·의미 중복 차단과 기존 가격 재알림 조건은 그대로다.

## 실행 빈도와 안전 간격

기존 Work 자동화의 GitHub workflow를 KST 08~22시 매시간 확인으로 늘린다. 매시간 7분 실행, 37분 안전 재시도 구조다. 한 시간 슬롯에 실제 발행은 최대 1건이며 발행 간 최소 30분 간격을 둔다. 따라서 현재 편성에는 하루 15개의 시간대별 기회가 있다. 이는 15건을 채우라는 목표나 임의 수량 제한이 아니라 현재 운영 시간·처리 속도의 범위다. 놓친 시간대 글을 한꺼번에 몰아 올리지 않는다.

기존 Cloudflare clock은 매번 main의 슬롯 설정을 읽으므로 그대로 사용하며 Worker 재배포나 새 예약을 만들지 않는다. 간격 대기 상태에서는 Cloudflare가 같은 시간대를 계속 dispatch하지 않는다. 기존 GitHub 37분 재시도나 다음 시간대에서 다시 확인한다. 이미 제출한 글은 재시도하지 않는다.

`pacing_wait`에는 다음 가능한 시각을 기록하되 제출 예약을 만들지 않는다. 날짜 경계를 넘는 직전 발행과 최근 결과 불명 제출도 간격 계산에 포함한다. 수집 오류·로그인 오류는 실제 오류로, 좋은 후보가 없는 것은 정상적인 건너뛰기로 구분한다.

## 보존과 검수

인증·원문 수집처·콘텐츠 범위·이미지 처리·발행 이력·중복 방지 원장·품질 하한은 변경하지 않는다. 이전 본문 수정인 '할인 기한' 사용과 삭제된 최저가 미확인 문장 금지도 유지한다. 운영 상태 원장이나 heartbeat를 편집해 시험 발행을 강제하지 않는다.

검사에는 좋은 6번째·11번째 후보의 선택, 낮은 품질/범위 밖/미검증 후보의 차단, 명시적 숫자/0/null의 차이, 같은 품질에서 다양성 우선, 전체 KST 시간대 일치, 최소 간격·결과 불명 중복 차단, 기존 Worker의 추가 슬롯 처리와 GitHub 예약 일치를 포함한다. 합성 자료와 모의 발행을 사용하는 검사이며 실제 카페 새 글 발행 시험은 아니다.
