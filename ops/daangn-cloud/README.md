# DealOps Daangn Cloud v6

운영 PRD: [PRD-growth-v4.md](PRD-growth-v4.md). 발행량 정책: [QUALITY-LED-VOLUME.md](QUALITY-LED-VOLUME.md).

## 실행

```sh
npm ci
npm run check
npm run preview         # 실제 출처 수집·초안 검수. 게시하지 않음
npm run preview:utility # 공식 생활정보 수집·초안 검수. 게시하지 않음
npm run cycle           # 통합 상업성·생활정보 운영 슬롯
npm run utility         # 생활정보 파이프라인 단독 진단
npm run growth:report   # 측정 가능한 성과와 미측정 값 구분
```

## 발행량

하루 5건은 고정 상한이 아니라 **기본 운영 목표**다. 검증된 좋은 후보가 충분하면 6~9번째 글도 추가 발행하며, 안전상 하루 최대 9건까지만 허용한다.

- 1~5번째: 기존 사실·출처·원고 품질 기준을 모두 통과하면 발행 가능
- 6~9번째: 원고 품질 88점 이상, 편집 점수 85점 이상, 출처 검증 완료 후보만 발행
- 상업성 글: 하루 최대 3건
- 생활정보: 하루 4건을 우선 확보
- 상업성 글 연속 발행: 허용하지 않음
- 발행 간격: 최소 50분
- 좋은 후보가 없으면 5건을 채우지 않음
- 5건을 넘겼다는 이유만으로 보통 품질 후보를 추가 발행하지 않음

통합 후보 확인 슬롯은 KST 09·11·12·14·15·16·17·18·19·20·21·22시다. 각 시간의 07분 실행이 기본 확인이고 37분 실행은 안전 재시도다. 같은 시간대에서 실제 발행은 최대 1건이다.

`growth-config.json`이 운영값의 단일 기준이다. 기본 목표, 하드캡, 추가 발행 품질 기준, 발행 간격, 시간대, 분야별 상한을 이 파일에서 관리한다. `enabled:false`는 발행을 멈춘다. `primaryRegions:[]`이면 전국 공통 정보만 수집하며 지역을 임의로 추정하지 않는다.

`collector → 사실 근거 → 편집 점수·목적 → 최근 100개 중복 QA → 원문 재확인 → 영속 예약 → 발행 → 결과·성과 기록`

발행 요청 전에 `state/publish-ledger.json`을 GitHub main에 저장한다. 예약 저장 실패 시 게시하지 않는다. 제출 후 응답이 불분명하거나 실행이 종료되면 `publishing`/`publish_unknown`으로 남아 후속 슬롯에서 중복 게시하지 않는다. 성공 시 원장에 복구 가능한 게시 기록을 함께 저장한다.

## 콘텐츠 구성

- 피드는 특가 중심이 아니라 생활 절약 정보 중심으로 운영한다. 목표 포트폴리오는 생활정보 65%, 상업성 특가·비교 35%다.
- 생활정보에는 환급·숨은돈, 요금 절약, 육아·시니어 혜택, 도서관·공공시설, 공식 정책·서비스 안내를 포함한다.
- 통합 선택기가 상업성·생활정보 비율, 연속 발행, 분야별 상한과 남은 생활정보 목표를 함께 판단한다.
- 최근 글의 제목 시작, 본문 구조, 문단 순서, 링크 위치, 마무리, 문장 리듬을 비교해 반복을 차단한다.
- 정보가 끝나면 억지 CTA나 애교 문장을 붙이지 않는다.

## 정보원·품질

- 판매처 Product/Offer 가격·KRW·재고·배송 조건을 재확인한다. 가격 차이 비교는 검증된 과거 관측가만 근거로 사용한다.
- 상품 JSON-LD나 조건을 확인할 수 없는 후보는 검토 큐로 보낸다. 다른 옵션 가격을 이전 가격으로 사용하지 않는다.
- 정책 날짜·금액을 코드에 임의 고정하지 않는다. 검토한 공식 자료와 원문 근거가 있는 사실만 사용한다.
- 책이음·공유누리·참가격·K-MOOC 등 공식 안내는 매 실행 원문을 다시 확인한다. 출처가 바뀌면 자동 게시를 보류한다.
- 단가 비교는 동일 상품 식별자·수량·자격 조건·배송 포함 금액이 검증된 경우에만 생성한다.
- 회원 제보는 동의·검수 승인·출처 검증이 있는 경우만 읽는다.
- 원문 조건 누락, 허위 경험, 과장, 미치환 예시, 중복, 미검증 숫자를 차단한다. 이미지 권한이 불명확하면 업로드하지 않는다.

## 학습

매일 23:40 KST 실제 게시 URL을 읽는다. 동일 유형·게시 시간·경과시간·측정 방식에 맞춰 비교하며 데이터 부족을 전체 평균으로 덮지 않는다.

전략별 서로 다른 게시물 20개와 최소 7일 관측이 필요하다. 반복 수집한 같은 글은 표본 수를 늘리지 않는다. 하루 1회, 변화 ±5%, 전체 가중치 0.75~1.25 제한이다. 측정 성공률 90% 미만에서는 학습을 중지한다. 조회수로 가입·공유·재방문을 추정하지 않는다.

회원 수는 공개 카페 화면의 `멤버 N · 게시글 N` 표시를 수집한다. 파싱 실패는 0으로 기록하지 않는다. 관측 불가 지표는 null이다.
