# 관측 지표 계약 v1

2026-09-07 구현 범위: 상태 비중 비교의 관측 저장. 과거 비교 수치·높음/낮음 라벨은 아직 공개하지 않는다.

- metric_version: status-share-v1. 확정 지연률이나 정시성이 아닌 관측 시점의 상태 비중이다.
- KST 현재 시각의 예정 1시간 구간, 10분 관측 버킷. 버킷 시작 후 2분 내 완료된 native cron 수집만 대상으로 한다. 버킷 뒤늦은 수집은 비교 표본에 넣지 않는다.
- 제공기관별 출발/도착 분리. ICN은 IIAC만, 나머지는 KAC만. 실제 운항편 기준, UNKNOWN 별도 건수.
- 알려진 상태 분모에 CANCELLED 포함. 분자는 DELAYED만. 결항 건수는 별도. 최종 DEPARTED/ARRIVED 상태의 확정 지연 기록을 의미하지 않는다.
- 데이터 변경 이벤트와 다른 테이블 airport_observations에 저장한다. 정상 전체 수집 이후 소스 잠금을 유지한 채 집계한다. 마지막 성공 시각이 같은 버킷에 있는지 확인한다.
- 동일 버킷은 최초 성공 기록을 유지한다. 부분 수집, 실패, 실행하지 않은 구간은 0으로 채우지 않는다. 성공한 소스의 조회 결과 0편은 기록한다.
- 입력은 최신 상태 테이블이므로 provider에서 사라진 편이 남아 있는 기존 read-model 정책을 따른다. API 전체 모집단을 완벽히 포괄한다고 주장하지 않는다.
- 현재/과거 모두 같은 metric_version, 공항, 방향, 예정시간 구간, 관측 minute_bucket을 사용해야 한다. 실제 observed_at 편차도 비교 시 점검한다.
- 향후 비교 공개는 현재·과거 최소 표본, 4개의 서로 다른 같은 요일 관측, 수집 누락 여부를 함께 확인한다. 20편 기준은 통계적 유의성을 보장하지 않는다. 숫자를 만들기 위해 이전 이벤트를 무조건 역산하지 않는다.
- 관측 저장 실패는 이미 성공한 운항 수집을 실패로 덮어쓰지 않는다. 내부 응답 observation.ok=false로 구분한다. 비교 API를 출시하기 전 기록 누락을 별도 품질 게이트로 확인한다.
- 기존 airport_hourly_metrics/route_daily_metrics 초안은 아직 연결하지 않는다. 관측 상태 비중과 확정 실제 시각 기반 통계의 분모를 섞지 않는다.

검증: KST 자정 및 UTC 입력 정규화, 버킷 재시도 멱등성, 소스별 공항 범위. 추가 운영 검증: 원격 D1에서 두 연속 native 버킷의 30개 공항/방향 관측 확인. 4주 비교는 충분한 실관측 이후 별도 구현한다.
