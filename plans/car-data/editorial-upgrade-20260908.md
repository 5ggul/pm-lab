# 내차데이터 콘텐츠 고도화 준비안

검토일: 2026-09-08. 상태: 분석·설계 완료, 새 원고와 기능은 아직 발행하지 않음.

사용자의 최신 요청은 첨부 제안과 편집 프롬프트를 분석하고 고도화를 준비하는 것이다. 첨부의 즉시 전면 구현 지시보다 이 범위를 우선한다. 진행 중인 차량 카드 미리보기 수정은 별도로 마무리한다.

## 판단

사양별 수치를 같은 조건으로 계산하고 차이를 해설하는 방향을 채택한다. 숫자만 옮기는 페이지보다 사용자가 선택 조건과 비용의 관계를 이해하는 페이지를 만든다. 페이지 수, 글자 수, FAQ 수, Schema 종류를 승인·노출 점수로 취급하지 않는다. 검색 상위·AI 인용·AdSense 승인을 보장하는 기준은 아니다.

Google은 고유하고 유용한 콘텐츠, 명확한 탐색을 권장한다. AI 검색에도 일반 SEO 원칙이 적용되며 특정 문체·분량·특별한 마크업을 요구하지 않는다. [AdSense 페이지 품질](https://support.google.com/adsense/answer/7299563?hl=ko), [Google AI 검색 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).

## 이번에 고정하는 범위

- 합계는 자동차세 + 연료·충전비. 구매가·보험·정비·감가·금융비용은 포함하지 않는다.
- 첨부의 크기 비교·크기 순위와 과거에 삭제한 홈 문구는 복원하지 않는다. 기존 제원 표는 유지한다.
- 기존 하이브리드 가격 차이 회수 도구는 별도 가정 도구로 유지한다. 차종 원고의 운영비 차이를 구매가격 회수 기간으로 해석하지 않는다.
- 3년·5년 예시는 유가·주행거리 고정 가정과 차령 경감 처리 방식을 명시한다. 1년 금액을 단순 곱한 값을 실제 미래 총소유비로 이름 붙이지 않는다.
- 공식 출처·라이선스 링크와 기술 URL에서 실제 호스트를 숨기거나 가짜 도메인으로 바꾸지 않는다. 내부 운영 용어만 소비자 본문에서 제거한다.
- 최종 도메인·색인·Search Console·IndexNow 활성화는 마지막 단계. 기존 noindex 유지.

필수 추가 확인:

1. 카탈로그 발행 연식·국내 적용 범위·각 사양의 캠/인승 묶음 확인.

5. 원고의 숫자와 1만·1.5만·2만km 표, 계산기 프리셋을 같은 데이터로 생성.

## 편집·데이터 구현 순서

1. **공통 계산·출처 계약**: 사양의 출처 ID와 조건, 날짜, 단위, 계산 버전을 먼저 고정한다. 문자열 label 외에 drive/wheel/seats/equipment를 비교 가능한 필드로 정리한다. 여러 인승이 하나의 신고 행이면 그 묶음을 보존한다.
2. **싼타페 단일 원고**: 데이터 확인 후 현재 상세 안에 직접답변 → 대표 사양 표 → 거리별 비용 → 실제 사양 차이 → 세금 산출 → 관련 비교 → 확인사항 → 출처 → 필요한 FAQ 순서로 작성한다. 내용 없는 섹션은 생성하지 않는다.
3. **원고+기능 일치 검사**: 정적 HTML·모바일 표·JSON-LD·계산기의 대표 사양과 단가 일치. 표만 붙인 원고, 차명 치환 해설은 보류한다.
4. **기존 비교와 모델에 확장**: 그랜저 휠별, 투싼 동력별, 쏘렌토 동력별처럼 실제 차이가 있는 주제를 각 모델별로 편집한다. 새 순위·새 계산기는 기존 기능으로 답할 수 없는 별도 목적일 때만 만든다.
5. **출시 설정 정리**: 사이트 origin, canonical, robots, sitemap, 구조화 데이터 URL을 한 설정으로 통합하고 기본값은 색인 꺼짐. 도메인을 정하기 전 임의 production origin을 만들지 않는다.

## 데이터 계약 초안

기존 주소를 우선 사용한다. 전기차 도구는 `/tools/ev-charge-cost/`, 휘발유 순위는 `/rankings/fuel-economy/`, 하이브리드 순위는 `/rankings/hybrid-fuel-economy/`, 전기차 순위는 `/rankings/ev-efficiency/`다. 첨부의 철자가 다른 URL을 중복 생성하지 않는다. 월간·출퇴근 계산과 3년·5년 예시는 기존 유류비/연간 비용 도구의 입력·결과 확장으로 충분한지 먼저 확인한다.

GitHub Pages의 정적 경로 404와 쿼리 ID 검증을 구분한다. `/cars/record/?id=잘못된값`처럼 같은 HTML 경로의 쿼리만 다른 요청은 브라우저 JS로 HTTP 상태를 404로 바꿀 수 없다. 당장은 탐색용 noindex와 명확한 오류·복귀 동선을 유지하며, 서버 상태 제어가 필요한 정책은 최종 호스팅 결정과 함께 설계한다.

페이지마다 `page_id`, `page_type`, `variant_ids`, `scope`, `source_refs`, `fuel_snapshot_id`, `tax_rule_version`, `published_on`, `modified_on`, `editorial_status`를 둔다. source_ref에는 URL·문서명·페이지·해시·자료 적용일·실제 확인일을 분리한다. 확인일이 새롭다고 모델 연식도 새롭다고 추정하지 않는다.

숫자 객체는 `value` 또는 `range`, `unit`, `source_ref`, `conditions`를 갖는다. 계산값은 원본 수치가 아닌 `derived`로 구분하고 입력 ID와 산식을 기록한다. 단일값/범위/누락을 구분하며 범위의 중간값을 대표값으로 임의 사용하지 않는다.

유가가 바뀌면 직접답변·표·메타·구조화 데이터의 파생값을 한 번에 갱신한다. 고정 예시라면 예시의 기준일을 유지한다. 제조사 자료일과 유가 날짜가 다르다는 이유만으로 오류로 보지 않고, **동일 계산 시나리오가 서로 다른 단가를 쓰는지** 검사한다.

PHEV는 전기·연료 운행 비중과 단위가 확보되지 않으면 단일 총액 순위에 넣지 않는다. 전기차는 사업자·회원·급속/완속 비중에 따른 입력 단가를 쓰고 임의 전국평균·충전손실률을 생성하지 않는다.

## 원고 생성 지시문 수정본

실제로 확인한 사양·출처와 버전이 고정된 계산 결과만 사용한다. 정보가 빠지면 추정하거나 TODO 페이지를 공개하지 않고 내부 보류 사유와 필요한 원문을 반환한다. 메타데이터·키워드 메모·품질 메모는 원고 본문과 구분한다.

본문은 짧은 직접답변, 숫자 표, 거리별 예시, 해당 모델의 수치 차이 해설, 세금 산출, 관련 비교, 확인사항, 출처, 필요한 FAQ 순서로 작성한다. 모든 섹션은 자료가 있을 때만 사용한다. 법령 설명은 공통 문장 재사용을 허용하되 모델의 차이 해설은 실제 사양 ID를 근거로 작성한다.

모바일은 사양/연비/연간 합계의 3열 요약과 펼쳐보는 세금·에너지비를 기본으로 한다. 상세 표의 정보를 삭제하지 않는다. 첫 화면은 차명·대표 조건·수치·범위를 짧게 제시하고 사진과 계산 진입점을 유지한다.

구조화 데이터는 현재 본문을 표현하는 최소 타입만 선택한다. 작성자는 실제 운영 주체 Organization으로, 게시일은 실제 최초 발행일로 쓴다. 실명 전문가·검증되지 않은 경력·리뷰·평점을 만들지 않는다. 갱신일은 실질적 수정 시점에만 변경한다.

## 구현 전 합격 조건

- 필수 출처, 국내 적용 범위, 사양 식별자, 연식 주장 근거가 모두 있다.
- 연비/전비 단위, 단일값/범위, 실제 비교 조건을 보존한다.
- 정상세액과 사용자 차령 조건을 구분하며 1,000/1,001/1,600/1,601cc 경계 및 EV 분기를 시험한다.
- 비용의 원 단위 표시 반올림 방식이 일관되고, 원시 계산값으로 차이를 산출한다.
- 메타·직접답변·표·계산 프리셋·구조화 데이터의 값과 날짜가 일치한다.
- 순위와 비교의 대상 범위, 제외 비용, 단가와 주행거리 가정이 보인다.
- 차종명 치환 문단이나 일반론으로 채우지 않았으며, 최소 하나의 유의미한 사양 차이를 해설한다.
- JS 없이 핵심 표가 보이고 320/375/390/430px에서 숫자·출처·입력·버튼이 잘리지 않는다.
- 빈 섹션, TODO, 준비 중, 가짜 연식, 근거 없는 실연비·안전 우열·인기 수치가 없다.
- 존재하는 내부 링크, 1개 H1, 고유 메타, 사실에 맞는 이미지 alt를 확인한다.
- 실패 항목은 상태를 보류로 남긴다. 자기점검 문구만으로 통과시키지 않는다.

이 문서는 준비 산출물이다. 신차 원문 재확인, 모델별 원고 작성, 코드 구현, 배포를 이미 완료했다는 보고가 아니다.
